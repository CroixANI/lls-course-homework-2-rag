# Промпт: Добавление логирования score для каждого чанка

Добавь вывод в консоль (print) значения score (уверенности / релевантности) для каждого найденного чанка в процессе поиска по FAISS-индексу.

## Контекст

В файле `src/rag/query.py` в функции `retrieve()` FAISS возвращает два массива:
```python
scores, ids = index.search(q_emb, TOP_K)
```

- `scores` — массив чисел с плавающей точкой, каждый из которых показывает, насколько релевантен найденный чанк запросу (косинусное сходство после L2-нормализации, диапазон от 0 до 1)
- `ids` — индексы найденных чанков в массиве `chunks`

Сейчас `scores` полностью игнорируется: функция возвращает только `[chunks[i] for i in ids[0]]`, теряя информацию об уверенности.

## Что нужно сделать

### Шаг 1. Изучи текущий код

Прочитай файл `src/rag/query.py`, особенно функцию `retrieve()`.

### Шаг 2. Измени функцию `retrieve()` в `src/rag/query.py`

После строки `scores, ids = index.search(q_emb, TOP_K)` добавь вывод в консоль для каждого найденного чанка:

- Порядковый номер чанка (1, 2, 3...)
- Значение score (округлённое до 4 знаков)
- Источник чанка (`chunk['source']`)
- Первые ~80 символов текста чанка (для читаемости)

Формат вывода должен быть примерно таким:
```
[RAG] Найдено чанков: 5 для запроса: "как взять отпуск?"
[RAG] #1 | score=0.8731 | source=hr_policy.md | "Для оформления отпуска сотрудник должен подать заявление..."
[RAG] #2 | score=0.7654 | source=faq.md      | "Отпуск оформляется через портал HR не менее чем за..."
...
```

### Шаг 3. Убедись, что логи не ломают существующую логику

- Функция `retrieve()` должна по-прежнему возвращать тот же тип данных (`list[dict]`)
- Не меняй сигнатуры функций `ask()`, `build_prompt()`, `ask_llm()`
- Логи должны выводиться до `return`, чтобы гарантированно появляться в консоли

### Шаг 4. Проверь результат вручную

Запусти `python src/rag/query.py` и задай тестовый вопрос. Убедись, что в консоли появляются строки с `[RAG]` и значениями score.

## Требования к коду

- Используй обычный `print()` — не нужно подключать модуль `logging`
- Не удаляй существующие print-сообщения с эмодзи (`📦`, `✅`, `❌`)
- Изменения должны затрагивать только файл `src/rag/query.py`
- Не рефакторь остальной код — только добавь логирование
