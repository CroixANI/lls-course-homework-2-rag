# Промпт: Реализация Query Expansion (LLM Rewrite)

## Контекст задачи

Сейчас запросы пользователя попадают в поиск «как есть». Короткие запросы (`sqli`, `xss`, `403`) или запросы с аббревиатурами плохо матчатся с чанками документов. Нужно добавить **этап умного перефразирования**: перед поиском агент анализирует запрос и при необходимости расширяет его до более полного и конкретного вида.

**Примеры расширения:**
- `sqli` → `SQL Injection vulnerability examples and prevention`
- `403` → `HTTP 403 Forbidden error causes and solutions`
- `как авторизоваться?` → остаётся без изменений (запрос уже достаточно понятен)

**Зачем это нужно:** Расширенный запрос содержит больше ключевых слов, что улучшает как BM25-, так и векторный поиск.

## Шаг 3. Реализуй функцию `expand_query()` в `src/rag/query.py`

### 3.2. Реализуй функцию

Добавь новую функцию **перед** `retrieve()`:

```python
def expand_query(query: str) -> str:
    """
    Расширяет короткий или неясный запрос с помощью LLM.
    Возвращает расширенный запрос или исходный, если расширение не нужно.
    """
    if not QUERY_EXPANSION_ENABLED:
        return query

    word_count = len(query.strip().split())
    if word_count >= QUERY_EXPANSION_MIN_WORDS:
        return query  # запрос достаточно длинный, расширение не нужно

    expansion_prompt = f"""Ты помощник для улучшения поисковых запросов.

Пользователь ввёл короткий или неясный запрос: "{query}"

Твоя задача — переписать этот запрос в развёрнутую поисковую фразу на английском языке, которая:
- Раскрывает аббревиатуры и сокращения
- Добавляет контекст (например, это ошибка, уязвимость, команда и т.д.)
- Остаётся краткой (не более 10-15 слов)

Верни ТОЛЬКО расширенный запрос, без пояснений и кавычек."""

    try:
        expanded = ask_llm(expansion_prompt).strip()
        if expanded and len(expanded) > len(query):
            print(f'[RAG][QueryExpansion] "{query}" → "{expanded}"')
            return expanded
        else:
            return query
    except Exception as e:
        print(f'[RAG][QueryExpansion] Ошибка расширения запроса: {e}')
        return query
```

**Важно:** `expand_query()` использует `ask_llm()`, поэтому её нужно определить **после** `ask_llm()` или вызывать по имени (функции в Python разрешаются в момент вызова, не определения).

### 3.3. Обнови функцию `ask()`

Добавь вызов `expand_query()` как **первый шаг** перед поиском:

```python
def ask(query: str):
    """Answer a question using RAG with query expansion and reranking."""
    expanded_query = expand_query(query)       # Шаг 1: расширение запроса
    candidates = retrieve(expanded_query)      # Шаг 2: гибридный поиск
    contexts = rerank(expanded_query, candidates)  # Шаг 3: реранкинг
    prompt = build_prompt(query, contexts)     # Шаг 4: промпт (с оригинальным запросом)
    return ask_llm(prompt), contexts
```

**Обрати внимание:** В `build_prompt()` передаётся **оригинальный** `query`, а не расширенный — пользователь должен видеть свой вопрос, а не переписанный.

## Требования

- Не меняй сигнатуры функций `retrieve()`, `rerank()`, `build_prompt()`, `ask_llm()`
- `expand_query()` должна работать корректно даже если Ollama недоступна (try/except с fallback на оригинальный запрос)
- Сохрани существующий формат лог-сообщений с префиксом `[RAG]`
- Не удаляй существующие print-сообщения с эмодзи (`📦`, `✅`, `❌`)
- Если реранкинг из шага 2.2 ещё не реализован — в `ask()` вызов `rerank()` можно пропустить, пока он не будет готов
