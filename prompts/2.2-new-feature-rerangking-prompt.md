# Промпт: Реализация Reranking (Cross-Encoder)

## Контекст задачи

После внедрения Hybrid Search (`retrieve()` возвращает Top-K чанков) нужно добавить **второй этап фильтрации** — реранкинг с помощью Cross-Encoder модели. Это позволяет убрать «шум» и оставить только те чанки, которые реально отвечают на вопрос.

**Схема работы:**
1. `retrieve()` возвращает **Top-20** кандидатов (из гибридного поиска)
2. Cross-Encoder перечитывает пары `(запрос, чанк)` и присваивает каждой паре точный score релевантности
3. В LLM передаются только **Top-5** наиболее релевантных чанков

**Зачем это нужно:** Bi-encoder (наш FAISS) быстр, но груб. Cross-Encoder медленнее, зато оценивает релевантность с учётом контекста запроса.

## Шаг 3. Добавь реранкер в `src/rag/query.py`

### 3.1. Импорт и инициализация

Добавь импорт `CrossEncoder` в начало файла:

```python
from sentence_transformers import SentenceTransformer, CrossEncoder
```

Инициализируй реранкер на уровне модуля (рядом с инициализацией `SentenceTransformer`):

```python
from config import (
    ...,
    RERANKER_MODEL,
    RERANK_CANDIDATES,
    RERANK_TOP_K,
)

reranker = CrossEncoder(RERANKER_MODEL)
```

**Важно:** `CrossEncoder` загружается один раз при старте — это нормально, первая загрузка может занять несколько секунд.

### 3.2. Реализуй функцию `rerank()`

Добавь новую функцию после `retrieve()`:

```python
def rerank(query: str, candidates: list[dict]) -> list[dict]:
    """
    Переранжирует список чанков с помощью Cross-Encoder.
    Возвращает Top-RERANK_TOP_K наиболее релевантных чанков.
    """
    if not candidates:
        return candidates

    pairs = [(query, chunk['text']) for chunk in candidates]
    scores = reranker.predict(pairs)

    scored = sorted(zip(scores, candidates), key=lambda x: x[0], reverse=True)

    print(f'[RAG][Reranker] Переранжировано {len(candidates)} кандидатов, оставлено {RERANK_TOP_K}')
    for rank, (score, chunk) in enumerate(scored[:RERANK_TOP_K], start=1):
        preview = chunk['text'][:80].replace('\n', ' ')
        print(f'[RAG][Reranker] #{rank} | score={score:.4f} | source={chunk["source"]} | "{preview}"')

    return [chunk for _, chunk in scored[:RERANK_TOP_K]]
```

### 3.3. Обнови функцию `retrieve()`

Чтобы реранкер работал с большим пулом кандидатов, `retrieve()` должна возвращать **`RERANK_CANDIDATES`** чанков вместо `TOP_K`. Измени только финальный срез результатов:

- Было: возвращаем `TOP_K` чанков
- Стало: возвращаем `RERANK_CANDIDATES` чанков

Это можно сделать, передав `RERANK_CANDIDATES` как параметр или изменив константу в вызове поиска внутри `retrieve()`. Реши самостоятельно, какой способ чище вписывается в текущий код.

### 3.4. Обнови функцию `ask()`

Добавь вызов реранкера между `retrieve()` и `build_prompt()`:

```python
def ask(query: str):
    """Answer a question using RAG with reranking."""
    candidates = retrieve(query)          # Top-20 из гибридного поиска
    contexts = rerank(query, candidates)  # Top-5 после реранкинга
    prompt = build_prompt(query, contexts)
    return ask_llm(prompt), contexts
```

Сигнатура `ask()` **не изменяется** — она по-прежнему возвращает `(answer, contexts)`.
